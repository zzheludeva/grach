# ГРАЧ / GRACH — «Пробуй новое, работай руками»

Название зависит от языка интерфейса: **ГРАЧ** для русского, **GRACH** для английского, португальского и испанского
(ключ `brand.name` в словарях; логотип, шапка и заголовок вкладки берут его оттуда).

Интерактивный MVP цифровой платформы для людей, которые создают вещи своими руками:
лента вдохновения и сообщество, обучение и мастер-классы, маркетплейс handmade,
ИИ-студия «Творческий пинг-понг» и кабинет автора. Интерфейс на 4 языках
(русский, английский, португальский (Бразилия), испанский), региональные настройки
России и Бразилии.

## Запуск

Нужен Node.js 20+ (на этой машине установлен локально: `~/.local/node-v22.23.4-darwin-arm64/bin`).

```bash
export PATH=~/.local/node-v22.23.4-darwin-arm64/bin:$PATH
npm install
npm run dev          # http://localhost:3000
```

Продакшен-сборка: `npm run build && npm run start`.

Откройте `/welcome` и войдите в демо-аккаунт или пройдите регистрацию.
Все действия сохраняются в `localStorage` (переживают перезагрузку и смену языка).
Сброс: «Настройки → Сбросить демо-данные».

### Локализация
- Язык интерфейса и страна — независимые настройки; смена страны не меняет язык.
- Язык предлагается по настройкам браузера (баннер), не по геолокации; выбор сохраняется.
- Fallback на английский; плюрализация через `Intl.PluralRules`; числа, валюты, даты — через `Intl`.
- Деньги хранятся как `{ amount, currency }`; конвертации нет — цена в валюте мастера с пометкой.
- Пользовательский контент хранится на языке автора; перевод — только по кнопке.
- Новый язык: словарь в `src/i18n/messages` + код в `LOCALES`. Новая страна: запись в `REGIONS`.
- Логические CSS-свойства и `dir` по языку — архитектура готова к RTL.

### Рекомендации в ленте
Счёт = интересы (+3) + подписка на автора (+4) + вовлечённость в категорию (0–3) +
популярность + свежесть; затем разнообразие (не два поста одного автора подряд),
и каждая 5-я позиция — «Новое направление» из неизведанной категории.

## Что работает в демонстрационном режиме

- **Авторизация** — локальная демо-сессия; пароль не отправляется и не хранится.
- **Данные** — в браузере (`localStorage`); Supabase не подключён, схема готова.
- **Оплата** — не производится нигде.
- **Доставка** — способы и цены демонстрационные. Статусы службы доставки не симулируются: мастер сам подтверждает этапы (фото готового изделия, трек-номер или ссылка), покупатель подтверждает или оспаривает. У старых демо-заказов остались демо-номера с пометкой.
- **ИИ-студия** — без `ANTHROPIC_API_KEY` работает на заранее написанных ветвящихся диалогах (подписано в интерфейсе).
- **Сообщения** — только в браузере, не доставляются.
- **Переводы публикаций** — заранее сохранённые демо-переводы у нескольких постов.
- **Видео** — показывается кадр, без воспроизведения.
- **Просмотры** — демо-счётчики; остальная аналитика считается из данных приложения, без прогнозов.
- **Фотографии** (товары, обложки, проекты) уменьшаются в браузере и хранятся локально; при нехватке места показывается ошибка. С Supabase — загрузка в Storage.
- **Проверка прав** — в демо её выполняет слой данных `lib/store.tsx` (только владелец меняет товар, мероприятие, проект; черновики и проекты не видны другим). Серверная проверка — RLS-политики и триггеры в миграции, она заработает после подключения Supabase.
- **Уведомления об изменениях дат мастер-классов и напоминания организатору** — внутри платформы (без email/push). Напоминания за 24 ч и 1 ч в демо проверяются при открытии приложения и раз в минуту; на сервере — `send_session_reminders()` по расписанию pg_cron.
- **Ссылка на онлайн-подключение** видна только записавшимся на конкретную дату и ведущему.
- **Видео в уроках** — внешняя ссылка (YouTube и т. п.), видео не загружается на платформу.
- **«Забронировано вне платформы»** — места в демо-данных, занятые не через приложение (подписано).

- **Свои мастер-классы и мероприятия** (Кабинет автора → Мои мероприятия): черновик, публикация, правка, отмена. Существенные изменения (дата, время, часовой пояс, формат, место, ссылка, стоимость, программа, условия) уведомляют записавшихся и добавивших в избранное — по одному уведомлению на человека, со старым и новым значением. Перед сохранением автор видит число получателей. Правка описания или названия уведомлений не создаёт.
- **Свои товары** (Мои товары): фото (до 6), характеристики, техника, вариант продажи, срок, регионы и условия доставки (тариф службы, фиксированная цена или бесплатно — учитывается при оформлении). Черновики, скрытие, удаление, просмотры и избранное.
- **ИИ-студия:** свободное поле ввода на стартовом экране (Enter — отправить, Shift + Enter — перенос), подсказки необязательны.
- **Проекты:** «Создать проект» превращает диалог в объект (идея, рекомендации, план, ссылка на диалог). Страница проекта: статус, план, этапы с отметками, материалы, инструменты, заметки, фото процесса и результата, «Продолжить с ИИ» с контекстом проекта, публикация во «Вдохновение» и создание товара — только по отдельному действию.
- **Поиск:** публикации, люди, товары, мастер-классы, мероприятия, обучение и свои проекты; общие и контекстные фильтры, сортировки по типу, метки активных фильтров, сброс, состояние в URL, панель фильтров на телефоне.
- **Данные:** локальная база автоматически обновляется с v3 до v4 без потери изменений.

## Итерация 3: что изменилось

- **Учебные материалы** (Кабинет автора → Мои учебные материалы): форма с обложкой, кратким и подробным содержанием, категорией, направлением, техникой, уровнем, материалами, фото, ссылкой на видео, шагами с иллюстрациями и ссылками. Черновик, предпросмотр, публикация, снятие с публикации, удаление; просмотры и избранное. В «Обучении» и поиске — только опубликованные.
- **«Мероприятие» удалено** как сущность: формы, страницы, вкладки, фильтры и тексты. Существующие мероприятия при обновлении данных стали мастер-классами (ничего не удалено, отменённые сохранили отменённую дату, записи сохранены).
- **Мастер-класс = шаблон + сеансы.** Шаблон заполняется один раз, даты назначаются отдельно (в т. ч. «Повторить» существующую). У каждой даты свои время, часовой пояс, место/ссылка, места, участники и статус; дату можно изменить или отменить отдельно. Изменение цены, условий или места в шаблоне не перезаписывает назначенные даты: автор выбирает — только новые даты, ещё и даты без участников, или все (с уведомлением участников).
- **Запись** — на конкретную дату, на одно или несколько мест; повторная запись на ту же дату невозможна, свободные места пересчитываются.
- **Напоминания организатору** за 24 ч и за 1 ч (название, дата, время, формат, число записавшихся), отключаются в настройках, не повторяются, только для актуальных дат.
- **Заказы:** «Готов к отправке» — только с фото изделия (уходит покупателю в сообщения), «Отправлен» — только с трек-номером и службой доставки или ссылкой. История с автором, временем, фото, треком и комментариями; покупатель подтверждает этап или оспаривает с причиной — заказ возвращается на предыдущий этап, мастер получает уведомление.
- **Мозаичный дизайн** этой итерации позже откатили к прежнему оформлению (чипы категорий, обычные заголовки разделов).
- **Данные:** локальная база обновляется с v4 до v5 автоматически.

## Итерация 4: что изменилось

- **Возврат «Назад»** ведёт туда, откуда открыта страница: учёт переходов во вкладке (`src/lib/nav-history.ts`, компонент `BackLink`). Роль, вкладка, поиск, фильтры и сортировка хранятся в адресе (`useQueryState`) и восстанавливаются: продавец возвращается в «Продажи», а не в свои покупки; чужой материал — в тот список, где его открыли. Если страницу открыли напрямую, ссылка ведёт в раздел по роли.
- **Заказы — два обязательных подтверждения покупателя.** (1) Мастер присылает 1–4 фото готового изделия и комментарий, покупатель подтверждает или отклоняет с объяснением; до подтверждения отправка недоступна, после отклонения заказ возвращается мастеру. (2) После отправки (трек-номер со службой или ссылка) покупатель подтверждает получение → «Завершён». Остальные шаги подтверждения не требуют. Обе стороны видят, чей ход. Если покупатель не отвечает: напоминание не чаще раза в сутки, через 3 дня — подсказка; мастер может отменить заказ до отправки с причиной. Автоподтверждения нет.
- **Кабинет автора:** «Активные заказы» выше «Рекомендаций»; в «Мои заказы» — вкладки «Покупки» / «Продажи».
- **Язык в шапке:** переключатель ru / en / pt-BR / es; страница, адрес и фильтры сохраняются, выбор запоминается, страна не меняется.
- **Отзывы и другие модальные окна:** поле ввода больше не теряет фокус после каждого символа.
- **Создание из «Обучения»:** кнопки «Создать мастер-класс» / «Создать учебный материал» открывают те же формы, что и в кабинете (`/learn/new/workshop`, `/learn/new/tutorial`).
- **Участники мастер-классов:** организатор добавляет зарегистрированного пользователя на свою дату (поиск по имени, @username или email) с проверкой мест и повторной записи.
- **Переписка:** «Написать организатору» на странице мастер-класса, «Написать участнику» в списке записавшихся. Используются обычные личные диалоги с привязкой к мастер-классу и дате; новое сообщение создаёт уведомление.
- **Мобильная версия:** проверены ширины 320, 375 и 768 px; исправлены переполнения сеток, заголовки, размеры кнопок, типы полей (поиск, URL, трек-номер).
- **Данные и сервер:** локальная база обновляется с v5 до v6 автоматически. Для Supabase — `supabase/migrations/20261116_iteration4.sql`: функции `order_transition`, `order_ready_answer`, `order_ready_remind`, `order_action`, `host_add_participant`, `search_people_for_host`, защита прямых изменений статуса и подтверждений, контекст сообщений и уведомления о них.
